# v0.34.0-qiwolf.6 · 通用 HTTP 透传与 MinerU 同步接入

新增独立 Rust HTTP 透传，用一个 Tokengo 入口承接原生人脸、CLIP 和同步文档解析接口。无需 Python 网关运行时，不解析业务正文、不包装成聊天模型。

- 最长路径前缀匹配、可选剥离、精确上游路径白名单；路由授权指定 VKey及其有效后代，仍受用户/父链、渠道、付费、预算、RPM和并发约束。
- 静态上游 Header 使用现有 AES-GCM 加密，配置读取不回显；入站 Bearer、x-api-key 和透传专用 api-key 均作为本地 VKey，先剥离再注入后端凭据。
- 请求和响应原始字节流转发，保留 query、压缩正文及重复端到端Header；禁自动重试、跳转、解压与环境代理，过滤hop-by-hop字段。支持总期限、上传限额及下游背压取消。
- 复用不可变按次价格和逐attempt持久账本。完成上游HTTP响应（含4xx/5xx）计1次；发送后结果未知保守扣预留额，requests和token不冒充零。无法测token的透传拒绝TPM限额身份。
- 渠道页新增透传CRUD与手动HTTP诊断；schema39为独立路由配置与内部渠道类型。手动root诊断记系统账、不扣用户预算；普通数据面健康请求仍按路由价格计量。透传管理暂不加入运维令牌动作清单。
- MinerU第一阶段仅接 `/file_parse` 与 `/health`，multipart字段为 `files`，返回内联Markdown或原ZIP。新增可选Python标准库客户端及合同测试；原生包的 `tools/mineru-gateway-client.py` 支持私有凭据文件，健康和上传均鉴权，拒绝跳转，大小受限且错误脱敏。

## 使用与交付

服务端、CLI、WASM与容器从同一提交构建。提供 Linux x86_64原生包、linux/amd64离线容器和GHCR版本/commit/latest标签；具体commit、镜像digest、CI和资产以本Release实际记录为准。校验SHA-256并按固定版本或digest部署。macOS上的AMD64仿真检查不等于ARM64原生发行或性能验收。

完整合同见 [开发文档](../passthrough-development.md)、[使用与API](../passthrough.md)、[部署](../deployment.md)及[容器部署](../container-deployment.md)。原生包携带匹配的完整 `docs/` 与可选客户端，容器仍只有Rust运行时，不安装Python。

## 边界

本版不实现MinerU原生异步tasks/uploads/files/jobs的动态ACL、URL重写、资源归属或按文档聚合收费；不支持CONNECT/WebSocket、协议升级或无法原样表示的URL。仅手动HTTP诊断，无定时HTTP探针。网关超时不代表上游后台任务取消。

发布前必须通过目标237的合成真实调用；具体目标验证摘要随Release记录，不以健康200代替文件解析。既有MT Photos、MCP或其他调用方不随安装包自动切流，也不自动退役LiteLLM。GPU服务偶发故障和长期稳定性仍需独立观察。
