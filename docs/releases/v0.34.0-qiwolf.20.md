# v0.34.0-qiwolf.20

本版修复长期运行时原生历史归属池达到4096条后，上游已成功但网关返回`local_state: opaque artifact ownership could not be persisted`的问题，并发布Key归属标签显示。Cargo版本仍为0.34.0，数据库schema41→42。

## 通用历史保留

移除单owner终身4096条硬上限。每个Key身份、归一模型及完整来源范围分别维护近期500条指纹软窗口；窗口以最近使用时间排序，合法续接会刷新时间。只有窗口外且闲置至少24小时的指纹才可回收，每次输出登记最多回收1024条。活跃记录允许超过500甚至4096条，不按总请求队列数量判断会话结束。

回收在同一归属池下次登记输出时触发；不是后台定时任务。原有30天闲置硬过期、全局100万指纹/10万会话、单响应数量与大小保护继续保留。整个池不再使用时仍由原有过期清理处理。细节见[保留规则](../native-history-retention.md)。

不要求调用方提供新header、换Key、升级SDK或修改记忆后端。此前专用stateless header方案已撤销，AG/HS调用端均已恢复原件。Key、渠道/账号及来源隔离继续生效；历史失效或来源不符时明确拒绝，不静默删输入或跨来源重播。长时间闲置的旧对话可能需要重新开始。全局容量或真实存储故障仍可能产生本地状态错误，不能保证所有存储故障提前发现。

## Key归属显示

管理员列表及最近调用显示“Key名 - 用户名称”，便于区分同名Key。保留原名称、权限和账务口径，不轮换Key。独立GPU面板改动不属于此发行包。

## 升级与回滚

schema42只增加`protocol_artifacts_owner_recent`覆盖索引，不改表字段、owner或摘要算法，不清空历史。升级前一致备份数据库、主密钥、配置和旧程序。旧生产程序已在带新索引的隔离库成功启动，合成历史保留；这不是生产回滚演练。回滚程序仍须保留升级后业务写入，不能直接覆盖旧冷备；旧程序也会恢复原4096硬上限问题。

## 验收边界

build-test完成本轮保留模块28项、数据库6项及相关HTTP188项，共222项定向检查；索引后关键HTTP35项重复通过，不重复加总，不冒充完整工作区测试。覆盖普通JSON/SSE满4096后新增、真实结构历史续接、冷回收、最近使用刷新、Key/来源隔离、回收与容量失败事务回滚、重开数据库及索引计划。

私有修复构建已通过既有Key真实JSON、SSE新加密材料及原样历史续接，均HTTP200，原池4096→4097，无新增专用头。此为合成模型接口验收，未发起新的Hindsight记忆写入任务。2万条样本索引后热查询约4ms、冷回收约15ms，不作通用性能保证。
