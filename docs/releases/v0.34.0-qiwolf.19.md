# v0.34.0-qiwolf.19

本版优化运行总览、模型与路由、自定义探针的加载，并修复普通调用被兼容诊断状态阻塞的问题。Cargo 0.34.0、数据库 schema41 保持不变。

## 管理页面性能

模型目录在一次请求内复用渠道、映射、评分与策略快照，消除按模型重复加载全目录。总览统计一次读取请求窗口，同时汇总各维度，仅另查渠道尝试；累计调用保留模型归一与请求重试去重口径。页面独立数据并发加载、就绪即显示；探针凭据备注并行读取，离开页面取消过期任务，后台标签页暂停轮询。

这些快照仅用于当前管理请求，不缓存执行权限。停用、授权、路由和配置变更仍在实际派发时复核。

## 诊断与正常调用

保存虚拟模型只检查配置，不发上游探测。兼容诊断由用户主动触发；未验证、失败、过期或检查中均不阻塞保存、正常请求或配置好的回退。生产不自动续验或启动 GPU 兼容探测。真实权限、预算、并发、请求及响应结构检查继续生效。

向量与重排保留完整请求，取消以诊断样本限制正常输入的行为。连接、超时、5xx与损坏成功响应可以继续下一授权目标；400/429按配置开关。匿名 Responses 的 opaque 续接在同一下游身份及完整来源范围内寻找唯一绑定，不要求客户端额外提供会话头；无法安全定位来源时仍明确拒绝，不能跨账号借用状态。

## 配置与升级

负载分配分为渠道 Key 优先/用户粘性、本地向量节点按请求轮询、虚拟模型目标顺序/时段三层。具体配置及相互关系见[渠道与 Key 池](../provider-key-pools.md)、[本地节点轮询](../maintenance/local-vector-balancing.md)、[共享虚拟模型](../shared-virtual-models.md)和[向量回退](../vector-fallback.md)。轮询不是多副本同时推理，也不保证 GPU 利用率相等。

从 qiwolf.18 升级无需新迁移。安装包不携带现有实例的 Key、用户、路由或私有配置。升级前备份状态及配置；恢复业务写入后不能直接用旧冷备覆盖新数据。

## 验收边界

源码附真实 HTTP 管理接口的 9 供应方、35 渠道、47 模型映射、60k 请求性能场景，以及新旧统计逐字段对照。build-test 的真实 HTTP 管理场景运行 20 轮，P95：模型与路由 104.39ms、总览统计 123.07ms、渠道列表 11.28ms；均低于 300ms。新旧统计与历史空值、Top50并列、平均值舍入及溢出处理有逐字段对照。复杂 60k 请求/80k 尝试场景的新旧结果逐字段一致，旧实现单轮 3275.56ms，新实现 20 轮 P95 169.83ms；累计调用 60k 行 P95 18.44ms。首轮完整工作区 1373 项通过、0 失败、5 忽略；最终统计模块另有 20 项定向回归通过，Web 147 项及 WASM 发布构建通过。后补定向测试不累加进完整工作区总数。公开资产结果随发行收据记录；合成测试不等于所有部署环境或外部供应方的性能保证。
