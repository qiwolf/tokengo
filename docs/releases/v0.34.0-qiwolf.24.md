# v0.34.0-qiwolf.24

本版整理反向代理来源 IP 修复、通用部署说明及此前 main 的 CI 测试时序维护。Cargo **0.34.0**、数据库 schema **42** 不变，没有新增 Rust 业务逻辑、数据库迁移、模型能力或依赖变更。公开发行正在准备；新版本精确提交、CI、附件、镜像与独立运行结果以[本轮发行收据](../acceptance/2026-11-02-qiwolf24-release/README.md)为准，不将旧版验收算作本版新测。

## 变化范围

- 补齐多层反代的真实来源 IP 指南，解释为什么来源可能成为 VPS 的隧道地址，并给出仅信任明确代理来源、覆盖伪造头的 Nginx 配置。
- 归档 237 的内网 Nginx 修复：VPS 已保留公网地址；内层先从受信任 VPS 恢复地址，再把来源头传给 TokenGo。仅修改 Nginx 配置，不是应用读取 IP 逻辑的修复。
- 纳入已在 main 合入的 `0e393f8` 测试维护：将错误响应的行为截止与路由、持久化、客户端初始化及外层 watchdog 分开，保留异常正文截止、容量释放、回退和终止事件检查。该提交此前[main CI](https://github.com/qiwolf/tokengo/actions/runs/41200992060)通过，但不代替本版精确发行提交的 CI。

## 当前证据与范围

237 来源 IP 修复已于 2026-11-02 上线。修复前公网健康请求在内层记录为隧道地址；修复后的标记请求在 VPS 与 237 记录一致的公网来源。公网伪造两个来源头未被采用；不可信本机直连仍记录实际连接地址。目标 Nginx 语法检查、平滑重载及 Nginx/TokenGo 健康检查通过。详见[现场收据](../maintenance/source-ip-20261102/README.md)。

上述是生产反代配置验收，没有为此发起付费模型推理，没有独立取得新增公网模型请求的数据库记录，没有改写历史请求。内网调用本来就可能显示内网地址，不承诺所有来源都为公网地址。

既有模型兼容、Terra `none`、推理设置 UI 等继续沿用 qiwolf.23 及更早版本的注明范围证据，本次没有重新覆盖真实厂商、全部模型或参数组合。来源、历史证据和未知范围见[持续核实清单](../provider-verification-checklist.md)。本次新包尚未作为生产完整程序包升级到 237；已经上线的是 Nginx 配置，不能把两者合并为新程序生产验收。

## 部署与回滚

**安装新二进制或容器不会自动修复已有反向代理。** 多层代理部署应按[来源 IP 指南](../reverse-proxy-client-ip.md)核对实际代理来源地址，备份后修改对应 Nginx；示例地址必须替换，不能全网信任转发头。应用监听端口限制在回环或受控网络，只允许可信代理连接。

237 配置回滚使用[现场记录](../maintenance/source-ip-20261102/README.md)的独立备份，不需要恢复数据库。应用整包升级仍须程序与 Web 同源码匹配，并保留数据库、主密钥和配置的一致备份；恢复写入后不能用旧整库覆盖新增账务或会话。既有 qiwolf.23 推理设置回滚约束继续适用，见[上一版说明](v0.34.0-qiwolf.23.md#升级与回滚)。不移动已经发布的标签或替换旧版资产。
