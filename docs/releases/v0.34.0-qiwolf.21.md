# v0.34.0-qiwolf.21

本版修复“新增模型别名已保存，却不在默认模型列表显示”以及“旧路由目标失效后无法从编辑器清理”的问题。Cargo仍为0.34.0，数据库schema42不变，无新增迁移。客户端断开仅完成原因调查，本版不修改客户端取消、超时或连接处理逻辑。

## 为什么别名会消失

同一归一逻辑模型名会继承已有路由策略。比如以前只允许来源A，后来A不再声明该模型，又在来源B新增同名别名，B不会自动加入原白名单；候选与允许来源相交后为空，默认仅显示可用模型的页面便把它隐藏。保存的映射仍在，实际状态是“全局启用，但没有可用连接”。

模型页现在提示当前分类中已启用但没有可用连接的模型，并提供查看入口。卡片明确区分全局停用与“已启用，暂无可用连接”，避免把来源范围问题误解为保存失败。

## 清理失效目标

路由编辑器现在列出失效的已选目标，显示原供应商、备注及连接编号；已删除的连接也能按编号识别。管理员可以逐项从草稿移除，明确选择当前来源后保存。取消修改或关闭窗口恢复已保存策略，移除操作本身不会立即写入服务器。

空白名单和残留失效目标继续拒绝保存；不会因旧来源失效就自动改用所有新来源。其他来源顺序、超时、重试、auto和本地分配设置保留。详见[维护说明](../maintenance/stale-route-targets-20261027.md)。

## 升级与范围

升级安装包不会自动替换任何实例的私有channel_ids；管理员应使用新界面显式移除失效目标、选择所需来源，再保存并读回确认。不需要改客户端、SDK、Key或记忆后端。本次不修改AG/HS，也不把正常后台任务取消当作模型故障重试。

schema42、历史保留和权限合同沿用qiwolf.20。升级前备份数据库、主密钥、配置和程序；回滚Web时可以保留已修正的模型策略，不能用旧整库冷备覆盖上线后的新写入。软件包不分发现场Key、路由配置或数据库。
