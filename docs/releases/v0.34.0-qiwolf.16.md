# v0.34.0-qiwolf.16

本版整合本地向量/重排节点轮询、OAuth 结构化输出与输出上限兼容、运行日志边界修复和重排用量识别。Cargo **0.34.0**、数据库 schema **40** 不变，无数据库迁移。

发行状态：已公开发布。精确源码[`2702757fe4728a814fe135f0c102155c908abfae`](https://github.com/qiwolf/tokengo/commit/2702757fe4728a814fe135f0c102155c908abfae)的[精确main CI](https://github.com/qiwolf/tokengo/actions/runs/40122964321)和[发布流程](https://github.com/qiwolf/tokengo/actions/runs/40124162546)成功，9个公开资产与GHCR镜像已独立验收，见[发布记录](https://github.com/qiwolf/tokengo/blob/main/docs/acceptance/2026-10-25-qiwolf16-release/README.md)。

## 主要变化

- 本地 Embeddings/Rerank 可配置 `local_strategy: "round_robin"`，按请求轮转获授权的节点起点，沿用已有故障切换；游标按调用入口、owner、provider和目标模型隔离。云端与OAuth仍保留用户粘性、来源固定和已提交流不重放的规则。这是进程内等权请求轮转，不是分布式加权调度，也不自动部署GPU服务。见[本地节点合同](../maintenance/local-vector-balancing.md)。
- Chat `response_format` 的 text/json_object/json_schema 映射至 Responses `text.format`，保留 schema、description、strict；OAuth格式回显保留在 provider_metadata，不改写返回内容。
- OAuth支持 `max_output_tokens`；Chat上限字段经转换，Responses也兼容 `max_tokens` / `max_completion_tokens` 别名。多个字段必须相等，否则出站前拒绝。OAuth校验整数且至少16、不超过已核实的来源输出上界及计费上界，不静默裁剪。
- 显式上限用于TPM和账务预占，省略时仍保守预占完整来源上界；未知订阅成本维持未定价。cap截断保留实际用量，Responses返回 incomplete/max_output_tokens，Chat返回 finish_reason=length。
- 同一 reasoning 项逐项事件与cap终态仅密文不同时，采用完整最终原项；不解密、不宣称密文等价、不拼接状态。其他字段冲突仍拒绝；buffered归属只登记最终密文，不能跨owner/session/source generation复用。
- 日志分段/长行按字节有界，截断标记计入限额，轮转失败不越过文件上限；限时日志级别用代次避免旧定时器覆盖新设置。机器令牌权限、撤销和审计先于运行时修改，失败不改变当前级别。
- Rerank meter识别限定到对应接口，诊断用量与账务使用真实上游语义，不把其他响应中的同名字段当通用计量，也不重写原始用量字段。

## 验证与边界

私有现场曾对当前Luna账号完成12项结构化输出、上限、别名、拒绝与账务验收；它不是本次公开包或所有供应商、模型、客户端的验收。公开发行要求合并源码完整测试、native/WASM同commit构建、容器隔离生命周期及发布后匿名产物验证。未做HS完整抽取/归纳或32k/64k等长输出压力测试；scope、schema和价格仍由实际来源合同决定。

升级已有本地向量池后应按最终来源身份刷新兼容证据；软件更新不自动注册节点或改写业务路由。若回退到不支持local_strategy的旧版本，需先清除该策略字段。保留用户配置、数据库与用量历史，勿用旧冷备覆盖升级后的账单。

## English

Adds opt-in request rotation for local embedding/rerank nodes, with entrypoint-scoped cursors and existing failover. Cloud/OAuth affinity and native session ownership remain intact. Adds Chat-to-Responses structured formats, validated OAuth output caps and Responses cap aliases, accurate truncation/usage settlement, bounded runtime logging and endpoint-scoped rerank meters. Token limits include reasoning, require at least 16 for OAuth and respect configured source/price ceilings; conflicting aliases are rejected. Opaque capped reasoning retains the exact final provider ciphertext without merging state or extending ownership. Cargo 0.34.0 / schema 40, Linux AMD64 distribution. Published as [v0.34.0-qiwolf.16](https://github.com/qiwolf/tokengo/releases/tag/v0.34.0-qiwolf.16); exact-commit CI and public artifact acceptance passed.
