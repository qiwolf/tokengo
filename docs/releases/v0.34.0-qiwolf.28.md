# v0.34.0-qiwolf.28 — 透传请求详情与Key列表性能

本版将透传详情中的内部标识替换为当前服务名称和调用时实际记录的路径，并移除用户Key列表逐条串行读取额度的等待。Cargo版本保持0.34.0，数据库升级至schema43。

## 行为合同

透传详情显示“透传服务（当前名称）”、实际渠道、请求入口和“上游接口”。请求入口为接收到的URI path，上游接口为这次实际转发的URL path；均排除query。旧记录没有这两个路径时显示“未记录”，缺少服务名同样显示“未记录”。当前名称不是历史名称快照，不根据现有路由猜测历史。内部endpoint/model分类保留，普通LLM实际模型、虚拟入口与接口展示不改。

Key列表响应直接附上该用户各Key的额度快照，面板不再为每Key串行发起额度请求。保留零额度、无限额、停用Key、冻结与未配置的不同含义；不扩大用户权限，不改变额度、Key原值或额度编辑流程。管理说明统一16px间距。旧服务端缺少额度元数据时新面板明确提示刷新服务端，避免误显示未配置。

## 数据库与回退边界

迁移43仅执行两条ADD COLUMN，追加nullable TEXT request_path/upstream_path，无默认、无UPDATE、无历史回填。SQL随原生包提供于deploy/migrations/43-request-paths.sql，SHA256为ce1ba5b193a20c67a89c2a7d14a7d3683bbd39b629d5b2018c6df1573c109bb3，包manifest记录schema与迁移源。旧q27发行程序对合成schema43库启动、读取旧记录、写入并读取新请求已经在build-test隔离实测；这不是生产回退演练。回退程序不应降级或删除新增列。
