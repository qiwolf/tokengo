# v0.34.0-qiwolf.14

本版整理账务管理工作流，修复上游模型映射无法移除、重新添加及共享模型候选缺失的问题。Cargo 版本仍为 **0.34.0**，schema **40**；没有数据库迁移，不自动改变既有用户和 Key 授权。已[正式发布](https://github.com/qiwolf/tokengo/releases/tag/v0.34.0-qiwolf.14)，发行源码 `1386fa2d410ece30e1a24009e21fa9a1979cdd01`，main CI 和发布流程均成功；公开产物的独立验收状态见下文。

## 账务管理

账务按额度管理、价格配置、用量账本切换。用户、Key、渠道与来源显示名称，当前有效配置和历史记录分开；额度支持调整、解除限额及冻结/恢复，保留累计用量与历史账目。查询、重置、返回最新页和分页各自独立，末页不提供无效游标。结算后当前占用显示为 0，原始预占保留在详情。透传服务价格显示真实服务名，并可进入对应服务配置维护。

本次仅清理已确认的临时测试配置：删除测试预算和孤立配置，归档历史身份并停用或撤销测试凭据；历史请求、尝试、账本、分摊与价格记录保留。历史主体仍可在历史账务中识别，不用无效配置充当当前管理对象。

## 上游模型映射

上游 Key 配置提供明确的“移除映射”操作，与停用分开。移除需确认，保存后才生效，取消编辑不写入；移除后可重新添加。重选已停用的模型会恢复启用并显示反馈，同一上游可配置不同本地别名，不再静默忽略操作。

模型增量更新与精确移除在同一事务中处理。已被共享或私有虚拟模型引用、移除后没有剩余获准来源的映射会返回明确的依赖冲突，整次保存回滚；不删除调用、账务、价格或其他 Key 配置。

## 共享虚拟模型

管理员显式指定供应方的共享目标可选取该供应方的有效模型，不再被普通模型的直接来源白名单误过滤。候选、保存、解析、排队后的实时复核和向量兼容指纹使用一致的来源集合；普通模型和用户私有策略仍遵守原路由白名单。模型总开关、来源、供应方、Key、OAuth 可用性及调用者的来源与付费权限继续生效，不开放底层模型直接调用。

共享模型新建或编辑时刷新候选，提供手动刷新和候选数量反馈；刷新保留尚未保存的调用步骤和编辑草稿。

## 生产真实调用与历史保全
