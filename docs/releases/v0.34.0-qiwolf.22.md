# v0.34.0-qiwolf.22

Cargo仍为0.34.0，数据库schema42不变。源码验收、公开发行和237运行版本分别记录；最终公开资产及升级结果以[本版发行收据](../acceptance/2026-10-28-qiwolf22-release/README.md)为准。

## 变化范围

本版整合qiwolf.21之后的本地修复：DeepSeek前导developer角色适配和Responses工具调用索引转换；模型用途恢复维护入口；多厂商兼容W01–W12的核心交付。只修改TokenGo，不要求客户端、DSH、AG/HS改动。

原生调用缺少上游总输出硬上界证据时，使用注明来源及置信度的本地预占估算，不因此停用模型。鉴权、额度、TPM及真实用量结算继续生效；估算不是厂商承诺的硬上限。

预算按精确来源、型号和原生协议解释；缓存及思考用量保留子集关系，不能重复收费。原生签名、密文及Kimi完整summary按原有来源/会话身份校验；工具strict省略、true、false保持语义，不能静默降低保证。角色折叠明确存在指令优先级损失，无法等价的形态保留拒绝。

MiniMax转换限定精确M3/M3.1来源的Chat split与公共Responses；no-split转换、带签名Messages等无法等价表达的具体请求明确拒绝。strict原值及可表示的raw思考历史保持可用，未充分验收只标注，不按缺少文档证明关闭整项功能。Ollama/vLLM运行时元数据只产生未验证候选，不能因为模型名称或软件自报就开启推理能力。

诊断与配置保存分离：打开静态诊断及保存不发外部请求。管理员可另行运行有15秒总时限、可取消且绑定精确来源的最小调用或标准API元数据采集；一次最小请求成功不等于工具、所有协议或整个账号均可用。取消不能撤销已产生的供应方用量。

各批记录见[第一批](../acceptance/2026-10-27-provider-p0.md)、[第二批](../acceptance/2026-10-27-provider-p1.md)、[第三批](../acceptance/2026-10-27-provider-p1-batch3.md)。[第四批](../acceptance/2026-10-28-provider-p1-batch4.md)取得服务端受影响699项、Web171项、OpenAI SDK24项及Anthropic SDK3项对照通过；硅基流动4个精确托管型号共14次真实网关调用通过。最终浏览器验收已通过；精确main CI为Rust1560通过/0失败/9忽略、Python13通过及WASM成功。9个公开资产、匿名GHCR、原生/容器及Key生命周期均独立验收通过；237已冷备后整包升级，公网Chat/Responses普通问答和账务通过，详见发行收据。历史全量1535项属于较早源码，不与最终结果累加。

官方DeepSeek任意字面标识复述仍未充分验收，官方直连也复现不匹配；普通问答通过不覆盖该未知，没有因此停用模型或Responses。

硅基流动托管模型实测不代替Kimi、GLM、MiniMax、百炼等官方账号。原方案的G21–G29/O01–O09是独立可选接入，本版不声明新增这些执行器。Ark文档版本冲突维持待核验。

## 升级和回滚

服务程序、CLI及Web须来自同一审阅提交。升级前一致备份程序、资产、数据库、主密钥和配置；不清空历史、不替换Key、价格或路由策略。恢复旧程序不能用旧整库覆盖升级后的账务与会话写入。

新增重排探针仍复用原Config.input；降级到不认识rerank探针类型的旧程序前，先停用或移除这类新增探针。

新字段runtime_identity为可选。未配置该字段的旧配置兼容；旧程序不认识非空字段。降级前用可读取该字段的新程序备份并移除受影响来源声明，或保留兼容程序；配置变化导致相关代次和手工默认重新确认。不要直接假定旧程序可以读取新配置。
