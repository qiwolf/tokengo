## 推理参数兼容

同一已授权入口的 Chat 请求，标准 `reasoning_effort` 和仅含 `effort` 的 `reasoning` 对象都可精确转换到 Responses。显式客户端 effort 优先于来源默认，仍受来源声明的档位约束。双字段相同合并，冲突或对象包含其他无法无损表示的属性时明确拒绝，不静默丢字段。原生 Chat/Responses、工具调用、会话绑定、不透明历史、流式输出及实时授权的现有边界保留。

现场修复前以同一既有用户和 Key 对同一入口实测：无推理参数及字符串 `reasoning_effort` 返回200；`reasoning:{effort:low}` 在本地转换阶段返回400、上游尝试为0。现场路由指向原生 Responses 的 OAuth 来源；反馈截图中将当前故障归因于上游的说法与现场审计不符。本版修复已复现的本地转换问题，不据此泛化重试所有上游400或修改渠道授权。

参数合同详见[协议说明](../protocols.md#chat-请求中的-effort-对象兼容)。
