Cargo版本仍为0.34.0，数据库schema42不变。本版发布准备中；本地实现与隔离验证已完成，生产部署、DSH真实调用、线上UI验收、精确main CI及公开资产验收结果将在发行收据取得后补齐，不能将此文档视为已发布或已部署证明。

## 变化范围

### Terra关闭推理的来源限定兼容

当前OAuth账号的最新目录未声明`none`，但同账号、同出口直接调用精确上游`gpt-6.1-terra`的Responses接口已返回HTTP200、completed及0个reasoning tokens。TokenGo此前把目录视为完整允许列表而误拦有效请求，本版在已实测的连接、精确模型及来源身份范围内补充`none`。

兼容只在官方OpenAI来源、同身份有效且明确支持推理的非空目录上生效；不改写原始缓存，不改变服务商默认，不把`none`静默改成medium。连接、地址、凭据、请求头、绑定账号或协议变化后，来源身份不再匹配就不继续授予此兼容。其他账号、接入、第三方来源或Sol不自动继承该结论；管理员人工覆盖列表仍可排除`none`。

### 自定义推理档位界面

供应商模型的推理设置分别展示上游声明、实测补充、内置兼容和人工设置。人工模式分为“跟随来源”“追加档位”“覆盖支持列表”：追加动态合并当前有效来源，覆盖只允许填写的值；人工填写不标为实测成功。

档位列表、追加/覆盖模式与默认值一次事务保存。默认选项跟随未保存的草稿实时变化，所选默认被移除时阻止误提交，不静默回落。`none`明确关闭推理，“沿用服务商默认”不补推理参数；客户端显式参数优先。

旧客户端省略模式及旧JSON数组配置继续按覆盖处理。来源或上游映射变化后旧人工声明失效。追加模式保留DeepSeek此前接受的原生别名，覆盖模式仍可排除。

## 升级与回滚

服务程序和Web必须来自同一审阅提交。升级前备份程序、Web、数据库、主密钥、服务配置及当前接入的推理设置，保留旧程序目录与可执行回滚步骤。不修改无关路由、Key、价格和历史。

追加模式在既有`manual_levels`列存储带mode/levels的JSON对象，无表结构迁移。旧程序不识别该对象：回滚前须用新程序将本次新增append设置转换为经确认的旧数组，或按备份精确恢复受影响连接/模型的推理设置；不要用升级前整库覆盖升级后的账务、会话及其他业务写入。验证过程创建的临时对象只在本次范围内恢复或移除。

默认选项和来源显示属于新UI；若只回退半套资产会造成前后端语义不一致，因此程序与Web一并回退。不要移动已发布标签；后补验收写入main和Release页面。
