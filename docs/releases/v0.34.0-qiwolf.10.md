# v0.34.0-qiwolf.10 · 停用Key删除修复

发布准备中；尚未公开。Cargo0.34.0、schema40，沿用qiwolf.9的Key交付与加密再次显示。

管理员停用用户Key后，管理员和本人现在均可从列表删除，不必先设法恢复或寻找撤销入口。仍在启用且未撤销的Key必须先停用或撤销，避免误删运行中的凭据。删除把永久撤销、列表移除与审计放在同一事务中，保留物理Key、父子链、账务及调用历史；父Key永久撤销后子Key也不能恢复调用。管理员停用的Key仍不能由本人重新启用。

前端列表与提交校验使用相同条件；删除确认明确告知永久撤销与不可恢复。本人和管理员删除接口均覆盖权限隔离、幂等、子Key及审计失败回滚。

## 验收与部署

完整源码测试、精确提交CI、公开原生包及容器验收结果待发布后补。237升级前先冷备数据库、主密钥、配置和原版本，切换后核对现有授权、真实调用与Key生命周期。尚未执行不写为已通过；发布后收据保存在main和Release说明，标签内文档保留构建时快照。

## 升级与回滚

本版不改变schema40，不自动更换用户Key，不调整既有模型调用名和授权。使用同一版本的服务端与WASM，备份数据库及加密主密钥；回滚使用同一次冷备的数据库、主密钥、配置和原二进制，不能只更换主密钥。
