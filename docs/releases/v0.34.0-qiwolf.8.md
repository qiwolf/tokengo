# v0.34.0-qiwolf.8 · 共享回退、服务授权与目录管理

本版汇总 qiwolf.7 后的共享虚拟模型、向量/重排回退、自动续验、回收站、透传服务授权和目录整理。Cargo 版本仍为上游 **0.34.0**；分发目标为 Linux x86_64 原生包与 linux/amd64 容器。发布构建正在 build-test 进行，本文不据标题声明公开发布成功。

## 行为变化

向量、重排多目标链先对所有授权来源做有界合成兼容探测。向量核对索引、非零有限数值、维度及相似度；重排核对索引、排序、分数与文档对应。兼容证据绑定用户、来源、实际映射及执行配置，不按模型名称放行；已验证链可对网络、超时、5xx和无效输出回退，400/429遵守开关。输入域、探测成本及局限见[兼容合同](../vector-fallback.md)。

证据在18小时提前自动续验、24小时硬到期，失败5分钟重试。逐来源与原参考比较；某个云端来源故障仅隔离该来源，健康且身份未变的 GPU 可独立续签继续服务。全局证据损坏或全部来源不可用才整体拒绝并提示。首次初始化、旧证据无参考或手动保存仍须完整检查，不能通过降级跳过初次核实；来源/权限变化按新指纹处理。

管理员可创建共享虚拟模型，把底层模型设为“仅内部调用”，只授权共享入口。普通用户不能直调底层或借私有策略绕过；隐藏只控制发现，不能替代访问限制。每次真实尝试仍检查权限、预算、价格及原生状态归属，提交后的流式输出不重放。共享/私有入口均支持回收站；恢复后保持停用，保留历史和审计，未增加永久删除接口。见[共享模型合同](../shared-virtual-models.md)。

独立“透传服务”页提供新增、管理、删除和检查；普通用户目录只返回获准服务的安全摘要。用户/Key/祖先 `allowed_services` 逐层收窄，并保留旧逐 Key 白名单语义；撤权及排队后的权限再次核实。服务删除保留账务历史，服务ID不复用，不宣称服务删除也有回收站。见[服务授权](../passthrough-user-access.md)。

新建用户自动生成初始密码，显示/隐藏只切换眼睛图标，按钮背景保持一致。保存成功后尝试复制账号、显示名和密码；失败明确提示并可重试。普通 HTTP 的原生剪贴板回退已在 macOS 验证，不能据此声称所有浏览器或权限环境均可自动复制。

模型与渠道按显式供应商及用途整理。展示名称、目录用途分别存储，保留 API 调用名、上游映射、来源ID、实际路由类型和执行顺序；改展示名不使兼容证据因管理字段失效。音频、工具等目录用途不承诺新协议支持。详见[目录展示合同](../catalog-presentation.md)。

## 验证与边界

已有源码阶段证据：build-test首轮服务器932项、Web122项，共1054通过、0失败、3忽略；目录用途补充后定向服务器26项、Web123项，共149通过、0失败。149含重复覆盖，不与首轮相加为独立测试数；这些不是完整Cargo工作区/doc测试。Linux服务端与配套WASM构建已通过，当前合并发布源码仍需单独核验。

现场实例已升级至schema40并完成有限真实调用：共享向量返回1024维、重排返回有效结果，底层直接调用403；真实材料仅为合成短文本，不代表业务UAT、所有模型或长期稳定性。浏览器验证供应商/用途筛选、展示名/API名分列、详情草稿保留与取消、透传管理和服务授权；普通HTTP系统剪贴板另行核验。配置保全、完整性、外键、账务待处理项及静态资源均有收据。详见[正式目录](../acceptance/2026-10-23-formal-catalog/README.md)、[服务管理](../acceptance/2026-10-23-services/README.md)和[共享/续验](../acceptance/2026-10-23-vector-shared/README.md)。

这些现场证据不证明后续GitHub附件或GHCR镜像与现场运行二进制摘要相同。发布身份、下载、镜像拉取与隔离运行分别验收；上一公开qiwolf.7附件保持原状。

## 升级与回滚

共享虚拟模型使用schema40；由schema39升级前，一致备份数据库、主密钥、程序、Web资产与服务配置。回滚需使用匹配的升级前数据库及旧程序，不能仅替换二进制，也不能丢弃升级后的写入。服务端和WASM从同一提交构建，固定版本或镜像摘要，按[原生部署](../deployment.md)、[容器部署](../container-deployment.md)操作；旧版Compose固定SHA交付和离线双标签机制保留。

旧版本不理解新增的共享入口、仅内部调用和 allowed_services 授权语义。回退须恢复升级前的程序、数据库、主密钥和配套配置；不要让旧程序直接使用 schema40 数据卷，以免权限语义退化。
