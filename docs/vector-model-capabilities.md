# 向量和重排共享入口：能力、兼容证据与负载

共享虚拟模型保留真实上游的接收能力。兼容检查中的文本长度、批次数量、候选数量是实测样本描述，不是网关为虚拟入口另设的接收上限。请求超过样本范围时仍按配置顺序交给实际模型；是否支持该负载、扩展参数和内部模型窗口，由对应上游决定。

网关不会截断原文、缩短查询、减少候选，也不会把未知参数静默丢掉。`max_chunks_per_doc`、`overlap_tokens` 等供应商扩展继续透传；如果某个来源不支持，它应返回实际错误，再由调用策略决定是否切换来源。超出样本范围不等于已证明所有来源在该范围内数值等价。

## 日常请求与证据的区别

普通调用保留身份、权限以及必要的输入结构检查；向量支持字符串、字符串批次、token 数组与 token 批次，支持 `float` 和 `base64` 编码。显式 `dimensions` 须为正整数，其实际支持情况由上游判断。虚拟入口不另外施加旧版 512 字符、16 条向量、128 篇重排、8192 总字符或 4 MiB 正文限制。

正常响应校验防止格式损坏或数据丢失：向量检查批次数量、唯一完整索引、维数以及有限非零数值；base64 按 little-endian float32 解码进行完整性校验，返回客户端的编码保持原样。显式请求维数时按该维数检查，其他请求按已核实的模型维数检查。实测样本的单位归一化结论不会成为正常请求的额外拒绝条件。

重排检查返回数量、唯一有效索引、有限评分以及评分降序。要求返回文档时，返回原文必须与对应输入一致。`top_n` 只影响调用者要求的返回数量，不表示网关先删去未返回的候选；所有原始候选都交给上游处理。

`/v1/embeddings` 与 `/v1/rerank` 的直接和虚拟调用共用 HTTP 正文资源预算，默认 64 MiB，可用 `TOKENGO_VECTOR_BODY_LIMIT_BYTES` 设置正整数的字节数；反向代理的正文预算也须相应配置。虚拟响应读取与直接调用一致，不另设旧版 4 MiB 响应限制。

传输层的通用请求预算、上游来源配置的超时与配额仍然适用。它们应与直接调用同类真实模型采用相同规则，不另设更小的虚拟模型预算。上游自己的 token 窗口、分块或截断行为仍属于上游能力与参数语义；网关的原文透传不能证明模型在其窗口以外完整计算了所有 token。

## 可选完整负载兼容诊断

保存不访问上游；完整 profile 仅在用户主动启动诊断时使用以下合成验收样本：

| 项目 | 检查样本 |
| --- | --- |
| 向量 | 300 条可区分的长文本，每条 4096 Unicode 字符；核对全部索引、维数、跨来源数值及首尾单条与批次映射 |
| 重排 | 300 篇可区分的长文档，每篇 4096 Unicode 字符，查询 512 字符；请求全部 300 项并返回原文 |
| 重排跨来源比较 | 按原候选索引比较评分，容差 0.02；允许接近同分的名次交换，拒绝具有显著评分差的逆序 |
| 证据绑定 | 来源身份、模型映射、用途、profile、首次完整检查时间，以及各来源输入和数值输出摘要 |

这些数字记录完成检查时实际覆盖的样本，不能用于拒绝更长、更大的正常请求，也不能作为通用等价性或模型权重一致的证明。完整探针有独立执行预算与诊断费用记录，不能把它的诊断预算复用成用户请求能力上限。

## 主动诊断和旧证据

已保存的来源身份和证据仍可读取，用于排查来源差异。完整新 profile 诊断成功后才更新诊断记录；失败不覆盖已有成功记录。诊断记录不作为正常调用或回退的准入合同。

生产服务不启动定时向量/重排兼容探测，不自动续验，也不自动重试失败诊断。仅用户主动点击或调用诊断API后，才执行轻量或完整兼容检查。未验证、失败、过期或缺少参考都不影响保存、正常调用和按配置回退，不隔离来源，不修改 GPU 优先、云端回退等既定调用顺序。实际请求的身份、授权、额度、预算和响应完整性校验继续生效。

本文描述实现语义；实际通过的版本、生产来源配置、300 篇真实长文档结果、超时和回退演练应以对应批次验收记录为准。

## 来源容量拒绝的回退

已识别的真实容量拒绝按本次请求处理，不表示整个来源故障。重排来源明确返回 `encoded_query_document_pair_exceeds_<tokens>_no_truncation_performed`，或向量来源返回已知的 physical batch 容量不足格式时，网关保留完整请求继续下一个已授权来源，不把普通400开关误用成容量回退的阻断条件。尝试记录使用固定原因和数字型请求形状，不写入原文，也不因此全局暂停账号或冷却健康来源。

普通参数错误、无效文档等400/422仍遵循原有策略，不会仅凭错误状态码自动重试。所有来源均不能处理时，保留真实上游容量错误的HTTP状态与正文，不伪装成网关兼容合同拒绝，也不截断后重试。

## 自建 BGE-M3 的真实模型配置

本轮自建模型的 GGUF 元数据窗口为 8192 tokens。向量后端使用 `ctx-size=8192`、`batch-size=8192`、`ubatch-size=8192`；重排后端总 context 为 32768、4 个并行槽，每个查询与文档对可使用 8192 tokens，适配器批次为 4。这些是实际部署参数，不是网关对所有模型统一规定的限制。替换模型时应重新核对模型元数据、显存和真实接口行为。

原生向量适配器默认不截断；超窗输入返回明确错误。重排适配器先核对完整查询与文档对，超窗时明确声明没有截断，让网关将完整请求交给后续来源。返回原文一致与编码阶段没有截断需分别验证。

BGE-M3 的云端与自建 GGUF 即使使用相同权重，也可能因分词器的空白处理差异产生不同向量。自建适配器现使用官方 `BAAI/bge-m3` 固定版本的完整 tokenizer：`tokenizer.json` SHA256 为 `21106b6d7dab2952c1d496fb21d5dc9db75c28ed361a05f5020bbba27810dd08`，运行库 `tokenizers=0.22.2`。字符串输入不做额外 trim、拼接、padding 或截断，官方编码完整 token IDs 后交给原模型；显式 token-ID 输入保持原义，模型权重和归一化不变。启动时核对文件摘要和特殊 token 布局。不能通过放宽兼容阈值来掩盖分词差异。

本轮两入口来源超时为 120 秒、总调用预算 240 秒；客户端读取超时须覆盖完整回退时间。客户端提前断开不能等同于后端不能接收该负载。

## 长文本的数值波动与 v4 校准

用户主动运行的短样本诊断仍要求每条向量余弦至少 0.999、范数比误差不超过 0.02。v4 完整向量检查固定向每个来源发送两次相同的 300 条长文本；不挑选较好一轮、不重试至通过。对每条向量，先测量两个来源各自重复调用的归一化 L2 距离，再检查四种跨来源配对中的最大距离：

`最大跨来源距离 <= min(0.1, 来源A整批最大重复距离 + 来源B整批最大重复距离 + sqrt(0.002))`

这里 `sqrt(0.002)` 对应原余弦 0.999 的基础误差预算；稳定来源仍保留这个标准。来源的数值实现波动可能在独立调用间转移到不同样本，故使用固定整批中实测到的最大重复距离校准来源误差；自身重复距离及跨来源距离均有 0.1 硬上限（对应余弦至少 0.995）。两个来源自身重复向量的平均余弦，以及逐样本最差跨配对余弦的整批平均值，仍须至少 0.999，以拒绝系统性方向偏差。范数、维数、完整索引和首尾批次映射检查继续执行。证据记录重复输出摘要、具体规则及预算使用情况；旧 v1/v2/v3 证据保持可读，只有用户主动启动完整诊断时才发送长负载。

这项校准来自同一云来源对相同输入重复调用亦会低于 0.999 的实测，并不证明所有供应商、所有文本都具有相同波动，也不替代中文召回或旧索引兼容性回归。它不会修改实际返回给用户的向量。
