# 部署者智能体运维令牌设计

日期：2026-10-21。状态：实施及必要验证已完成；公开分发版本为 v0.34.0-qiwolf.5，以 Release 实际产物为准。

## 目标与依据

部署者在控制台签发独立令牌，交给自己信任的智能体；智能体无需 root 密码、浏览器 Cookie 或兼容登录会话，即可用 HTTP API 完成日常运维。第一版仅一种固定权限：**站点运维**。不设 scope 选择、角色层级、组织授权、OAuth 应用或令牌父子链。

依据：`docs/account-login.md` 的“脚本化运维”记录当前兼容会话；`routes/accounts.rs` 的 RootGrant 区分账号与兼容会话；`routes/admin.rs` 的 PanelAuth 保护渠道、设置、凭据 reveal 和维护接口；`routes/identity.rs` 的 AdminAuth 还接受显式获准的管理员 VKey。新能力不得从这些类型的名称推定权限，必须逐个动作登记。

本文中的默认值、API名称和边界均为设计建议，现已作为本次实施基线获用户确认。当前已有浏览器/VKey/兼容会话合同继续有效，原文不提前改成已实现状态。

## 部署者与智能体的使用流程

1. 部署者以 root 登录控制台，进入“设置 → 运维令牌”，输入名称、有效期，并确认当前密码。
2. 创建成功只展示一次完整令牌，同时给出实例地址和 Bearer 调用示例。列表以后只显示名称、标识、到期时间、最近使用时间和状态。
3. 部署者将令牌配置到智能体已有秘密存储中，不要求把 root 密码或令牌写进对话、代码仓库或通用知识库。
4. 智能体先调用 `GET /api/ops/me` 核对站点与令牌身份，再调用 `GET /api/ops/capabilities` 取得实际获准动作，随后访问现有业务管理 API。
5. 部署者可随时撤销单个或全部运维令牌。轮换采用“创建新令牌 → 验证 → 替换智能体配置 → 撤销旧令牌”，不增加单独的刷新/轮换机制。

这是 HTTP API 运维能力，不提供服务器 shell、宿主机重启、容器升级或文件系统访问。渠道探测可能调用供应商并产生费用；令牌不自动授予用户意图之外的操作授权，是否先请示仍由部署者与智能体的使用约定决定，服务端第一版不建设审批工作流。

## 一种权限与固定边界

所有运维令牌权限完全相同，均覆盖整个站点，不按用户、供应商或渠道分割。不提供只读档、局部授权或可勾选 scope。多把令牌只用于区分不同智能体、审计和分别撤销。

| 操作类别 | 站点运维令牌 |
| --- | --- |
| 健康、统计、脱敏运行日志、请求诊断元数据、审计记录 | 允许；不返回原始提示词/响应正文、原始报错体、Cookie、认证头或凭据快照 |
| 供应方、渠道、模型目录/映射、路由、fallback/冷却策略 | 允许读取和配置，包含增删、启停、调整顺序及重新探测；沿用现有对象删除/引用校验 |
| 供应方凭据 | 允许提供新凭据、替换、禁用；查询只返回安全元数据和掩码，禁止 reveal 现存密钥 |
| 普通用户、其登录凭证、VKey及授权 | 允许现有业务管理操作，含普通用户密码重置、停用/恢复与归档；不得创建/改造 root 身份，继续沿用既有归属、不可复活及账本保留规则 |
| VKey/Gateway Key 签发和撤销 | 允许，新增 secret 仅创建响应一次返回；不允许读取历史 secret 或获取面板会话 |
| 定价、预算与配额 | 允许现有业务 API 操作；不允许篡改已结算账本或删除审计 |
| 系统设置与维护 | 仅登记的非安全设置：路由参数、探测、限流/并发、日志级别、保留策略；不得直接提交任意 settings 键值 |
| root 登录名/密码、安全重置、会话管理、运维令牌管理 | 禁止，必须由部署者使用浏览器 root 会话操作 |
| 任何历史凭据 reveal、OAuth 身份凭据导出、解密密钥、DB/配置原件导出 | 禁止；OAuth授权/账号绑定第一版仍由部署者操作 |
| 数据库恢复、账本清空、历史数据立即 prune、审计删除、整体重置、宿主部署与重启 | 禁止；现有浏览器维护入口不因此取消 |
| `/v1/*` 推理与用户自助 API | 运维令牌本身不作为此类鉴权凭据；调用推理须单独使用获准的推理 Key |

**信任边界：这是高权限的站点管理员凭据。** 智能体可以修改流量目的地、替换上游凭据、创建业务 Key 或调整费用策略；即使禁止 reveal 也不能据此声称能隔离恶意智能体。能创建推理 Key也意味着它可能间接获得推理能力，不承诺“完全不能发起模型调用”。不适合第三方不受信的智能体，若以后要接入再另议权限分层。

同一个 handler 如混合了安全和非安全动作，应拆分或对输入字段明确白名单验证后才对运维令牌开放。禁止依赖按钮隐藏或前端过滤作为权限控制。新接口默认不在运维清单中，必须显式登记及测试后开放，不能自动继承 `/api/*`。

## 令牌生命周期

- 名称必填，1–64字符；建议按用途命名，例如“部署维护智能体”。无需新增智能体账号。
- 有效期默认90天，允许选择1–365天的整数；不提供永不过期。到期后不可延长、复活或自动刷新，只能创建新令牌。每站点最多20把未撤销且未到期令牌。
- 建议格式 `tgo_ops_<public_id>.<secret>`。secret 使用系统密码学安全随机源生成32字节，再编码；不得用时间戳、密码、模型输出生成。public_id只用于定位/脱敏展示，不具有鉴权效力。
- 数据库只存原始完整令牌的带域分隔 SHA-256 摘要，明文不持久化、不使用可解密存储。它是高熵随机凭据，不复用密码 Argon2 验证流程。验证长度/格式有界，摘要比较使用恒定时间方式。
- 有效期自创建时刻起算，使用服务器 UTC 时间；最近使用时间更新不续期。显示时可转换为本地时区。
- 单个/全部撤销立即阻止后续授权；撤销记录保留审计，默认不可硬删除。服务重启不能复活令牌。
- root 普通改名、改密默认不影响独立运维令牌，避免例行密码轮换中断自动化；控制台须明确提示这个区别。运维令牌可单独全部撤销。root“安全重置/疑似泄露恢复”必须同时撤销运维令牌，不只撤销浏览器和兼容会话。
- 撤销成功后新请求拒绝；已经提交的操作不回滚。写操作在业务事务提交前复核有效性：外部探测已发生时不能撤回外部副作用，但撤销后不得再把其结果提交为配置更改。已返回读数据不能收回。

## API合同（建议）

所有管理请求使用 `Authorization: Bearer <token>`。只允许一个 Authorization 头；拒绝重复头、Cookie混带以及 query/body 传令牌；Cookie+Bearer仍为401。识别到 `tgo_ops_` 后进入独立验证分支，失败不得回退尝试其他身份。

无Cookie的机器Bearer不使用浏览器CSRF机制；浏览器令牌管理继续要求 Cookie、同源及 `X-Tokengo-Panel: 1`。令牌不产生浏览器会话，不换取root会话，不嵌入URL。

| 接口 | 凭据和行为 |
| --- | --- |
| `GET /api/ops-tokens` | 仅浏览器root；分页返回安全元数据，不含摘要或原始令牌 |
| `POST /api/ops-tokens` | 仅浏览器root且确认当前密码；输入 `{name,expires_in_days,password}`；返回 `{token,secret}`，secret为一次展示的完整Bearer。验证密码后事务内复核root会话/凭据版本，避免撤销或改密竞态 |
| `DELETE /api/ops-tokens/{id}` | 仅浏览器root，撤销单把；不要求再次输入密码，以便迅速止损；重复撤销保持幂等 |
| `POST /api/ops-tokens/revoke-all` | 仅浏览器root且确认当前密码；撤销事务之前已存在的全部有效运维令牌 |
| `GET /api/ops/me` | 仅有效运维令牌；返回部署稳定非秘密 `instance_id`、令牌id/名称、固定权限 `site_operations`、expires_at、合同版本；不返回root资料或secret |
| `GET /api/ops/capabilities` | 仅有效运维令牌；返回合同版本、登记动作的method/path模板与说明文档链接。与服务端动作注册表同源，不是第二套授权策略 |
| 现有业务API | 对明确登记动作接受root或运维令牌；保留已有VKey管理权限，不自动扩大其范围 |

创建响应的 `token` 是不含摘要的安全元数据对象，`secret` 是完整 `tgo_ops_...` 字符串。列表中的状态为active/expired/revoked；创建人记录root account id；不提供PATCH、刷新token或请求延期接口。

机器接口身份无效、到期、撤销统一401 `invalid_operations_token`；身份有效但动作不允许403 `operations_action_forbidden`；混用Cookie/重复鉴权头401；未登记路由若实际存在则403，真正不存在则404。格式错误400，资源业务冲突409（沿用旧接口已有错误语义时不强行改为409），认证资源繁忙/节流429，存储故障5xx；鉴权无法读取状态时失败关闭，不能继续执行。禁止依据明文token差异暴露具体失效原因。

所有令牌管理和机器认证响应为 `Cache-Control: no-store`。默认不开放跨域；远程访问要求TLS，由部署方式/反代配置保证，loopback测试可HTTP。不盲信任客户端 `X-Forwarded-Proto` 作为安全证明。不新增静态IP白名单、mTLS、OAuth或SDK。

## 服务端落点与审计

新增独立 `operations_tokens` 表：`id,public_id,name,token_hash,created_by_account_id,created_at_ms,expires_at_ms,revoked_at_ms,last_used_at_ms`；索引public_id及状态查询。新增schema migration，不把数据塞进panel_sessions、VKey、上游凭据池或settings。一个root签发者身份，不依赖可变username/密码hash相等关系。安全重置调用统一撤销函数，与账号安全操作同一事务。

新增有类型的机器身份与业务鉴权 `ManagementActor::{RootSession,OperationsToken,VKey}`。以动作注册表明确允许的凭据种类：原始 `PanelAuth`、`RootGrant` 及账号安全入口保持root语义；只对允许的业务handler逐项接入“root或运维令牌”，users/vkeys沿用既有VKey逻辑并增加独立actor分支。严禁让运维令牌通过 `PanelAuth` 后间接被识别为root或被写成 `panel_admin`。

审计记录机器actor_type、actor_id、action、target、请求关联id、成功/失败、时间；新令牌创建/撤销也记录创建人/撤销人。写操作审计随业务事务原子提交；没有落盘审计不能确认配置修改成功。认证失败记录不含原始token的有界事件和原因类别，未知token不以攻击者输入作为无限增长的标签。last_used可每分钟合并写入，界面标明近似；撤销/到期校验不可依赖该缓存。

沿用现有数据库审计结构，补机器actor字段或明确的metadata投影，不能假装机器操作由root本人发起。不保存完整请求/响应体，凭据、密码、headers和原始模型输入均不进入审计。列表、日志、错误、导入导出路径均须检查间接泄漏。

鉴权有长度/头数量限制；使用现有受控认证资源上限，DB异常拒绝；业务端点已有探测/并发限制继续生效，不把运维Token接进VKey账务/TPM预占系统。主动探测须审计，并在合同说明潜在供应商费用。

## 兼容与交付范围

首版保留 `/api/auth/login` 的兼容Bearer，不在同一发布中删除。文档将新运维令牌作为推荐自动化入口，将旧会话说明保留在兼容章节；不把旧会话无提示转换为新令牌。此前Issue #4的scope诉求本次仅解决独立凭据、生命周期和机器入口，不宣称实现了细粒度scope。

第一版交付：数据库及鉴权、上述令牌接口、逐动作业务接入与返回脱敏、控制台基本管理、审计、脚本化文档和隔离验收。控制台只需列表、创建、一次展示与撤销，不增加完整智能体平台。当前仅定义流程，不生成UI设计稿。

明确不做：多档权限、按渠道scope、自动续期、智能体账号注册、任务编排、MCP服务、远程shell、发布部署控制、单独CLI/SDK、OAuth授权服务器、云端秘密托管。使用者可通过任何支持HTTP与秘密存储的智能体接入。

## 验收标准

1. root浏览器创建令牌；关闭一次展示后无法再次读取secret；存储仅有摘要，列表/日志/审计不泄密。
2. 智能体无root密码、无Cookie、无legacy登录即可自检身份，读取并修改测试渠道，运行探测及路由配置，审计明确归属于本令牌。
3. 固定允许清单逐项正向验证；账号安全、令牌再签发/撤销、所有reveal、安全设置写入、混合settings输入、原件导出、prune/恢复入口均负向验证，不能只测按钮或HTTP状态。
4. 普通用户与VKey管理、定价预算等允许动作保留既有业务约束，尤其root不可创建/删除、祖先策略不得绕过、账本不可清空；允许新Key的一次secret回显不变成历史secret导出。
5. 令牌不能用作 `/v1/*` 推理凭据，机器令牌失败不回退；旧Cookie/VKey/legacy会话原有能力不变。
6. 令牌有效期为绝对时间；单个/全部撤销、重启后撤销保持有效，默认90天和1–365天校验通过；过期令牌不计入20把有效上限。
7. root改名/改密保留机器令牌；安全重置撤销机器令牌；签发、撤销、并发写提交和密码校验竞态验证通过。
8. 原样运行新文档示例，在独立临时库完成自检、读写、撤销后401；无真实业务数据/供应商secret。需要探测时使用受控mock上游；实际供应商调用和目标部署另行标注。
9. 机器诊断响应严格投影；header/body/query令牌泄漏、301/302跳转携带secret、CSRF/Cookie混用和凭据误分类有定向测试。
10. 发布清单列出具体接入的method/path，不以“支持所有管理API”替代验收。实施任务应先从当前路由表生成逐项清单和字段白名单，再改鉴权；漏登默认拒绝。

## 当前设计判断

建议采用固定“站点运维”权限，而非把root账号完全复制给机器。根账号安全和运维令牌生命周期由部署者保留；日常站点业务运维统一开放。这样符合“一种权限等级”，同时避免智能体自行取得永久控制权。仍需部署者信任智能体，不将其包装成不受信代理的安全沙箱。
