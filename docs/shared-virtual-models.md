# 管理员共享虚拟模型与内部目标

管理员在“共享虚拟模型”中统一维护顺序或时段调用链，再在用户/VKey的模型权限里授权共享入口名。普通用户只需该入口的模型权限，不必同时获得底层逻辑模型名权限。共享入口仍受调用者的渠道白名单、付费权限、用户/Key/祖先Key限流、并发、预算与冻结约束；每次实际派发重新检查当前授权和配置版本。

例如：共享 `embedding-main` 的第1目标为云端BGE-M3，第2目标为自有GPU BGE-M3；共享 `rerank-main` 同理。普通用户只授权这两个入口。底层逻辑模型在“模型”详情中设为“仅内部调用”后，用户不能直接指定该名字，不能通过auto或用户私有策略绕过；只有管理员共享入口可委托使用。此设置按逻辑模型名生效，覆盖该名字的全部来源，不是按GPU/云端连接单独隐藏。

“兼容隐藏”仍只控制发现：不出现在公开模型清单及auto中，已获授权的旧客户端仍能指定名字。“仅内部调用”是调用权限隔离，用户列表/新增授权选项不展示，原有历史授权可保留作撤销操作，但不会恢复直调能力。全局停用则连共享入口也不能使用该底层模型。

## 配置步骤

1. 在管理员“共享虚拟模型”创建一个不与标准或私有模型重名的入口，选择真实供应方与模型，设置目标顺序、时段及400/429切换条件。无需对每名用户复制策略。
2. 保存只检查配置并持久化，不访问上游。需要排错时，可独立启动单目标或完整兼容诊断；未检查、失败或过期均不影响保存、正常调用和按配置回退，不会自动隔离来源。诊断只由用户主动启动，不在启动或定时任务中执行。样本、输入域与输出检查见[向量回退说明](vector-fallback.md)。兼容诊断记入管理员系统诊断账本，不扣普通用户额度。
3. 对不允许用户直调的底层逻辑模型，打开“仅内部调用”。管理员共享编辑器仍能选择它们，普通用户私有编辑器不能选择。
4. 在用户/VKey模型权限仅选共享入口。模型和渠道权限分开：若渠道已有白名单，必须包含允许该入口使用的来源；撤去其中一个来源后链路不会越权使用它。
5. 用户用共享名字调用原来的Chat、Responses、Messages、Embeddings、Rerank等适合端点。协议能力、模型用途和原生会话绑定仍适用；不会把不同用途混成一条链，也不允许虚拟入口递归。原生会话已绑定来源、流式响应已经提交等不安全切换场景仍受网关原有保护。

共享名全站唯一，不能与任一用户私有名或标准模型重名。停用后保留名称及历史，不能借同名私有模型绕过停用。共享模型列表和用户创建Key时的选项均按当前权限及可用目标计算；普通用户只能获取可调用名称，不具备管理员共享策略编辑权。

## 顺序、时段与目标内负载均衡

顺序模式按第 1、2、3 步依次执行所有目标；时段模式选择该时段的目标位置及其顺序。时区只支持 `Asia/Shanghai` 和 `UTC`。区间开始包含、结束不包含，同日不能重叠；跨午夜需拆成两段。未命中时用默认目标链，默认链为空则返回当前时段不可用。API 的 `target_positions` / `default_positions` 从 1 开始，例如 `[2,1]` 表示先第 2 目标，再第 1 目标；顺序模式不附带时段或默认链。

共享目标的网络、超时、5xx 等来源故障可以继续后续目标，向量/重排还会对无效 JSON、错误索引或维数等结构故障回退；400/429 则仍按 Key 和目标的显式开关处理。不要将普通用户私有聊天链的“仅 400/429 跨目标”规则套用于管理员共享链。原生会话来源固定、已提交响应的安全限制仍优先。

目标之间使用配置顺序，目标内部再使用供应方 Key 策略；若目标是多地址本地向量/重排，可对目标逻辑模型设置 `local_strategy: "round_robin"`。例如“云端主目标 → GPU 备用目标”中，GPU 备用目标可以包含两个本地服务节点并轮流接单；主目标成功不会提前消耗备用节点的轮询。见[三层策略](provider-key-pools.md#三层策略账号节点虚拟目标)及[本地节点配置](maintenance/local-vector-balancing.md)。

## 超时与核对方法

长请求可由管理员在“系统设置 → 请求等待时间 → 编辑等待时间”调整“非流式完成（秒）”和“调用与切换总预算（秒）”。前者限制非流式单次尝试，后者包含等待、重试和回退；页面各项允许 1～3600 秒，修改影响所有继承全局值的调用。调用端和反向代理也须允许相应等待时间。当前模型路由编辑器及其写 API 只支持已接入的真实逻辑模型，不能通过共享或私有虚拟名保存独立超时。目标逻辑模型的本地节点轮询仍按该目标策略执行，但其超时覆盖不会自动应用到虚拟入口。运行时保留读取虚拟名下既存覆盖的能力，这不代表已有面向用户的配置入口。

保存并授权后，用共享入口名字发起普通请求，核对流水中的入站名、实际目标、来源、尝试顺序及实际计费。需要比较来源数值时再主动启动兼容诊断；诊断失败或过期不影响运行，也不会自动隔离来源。向量/重排完整诊断预算与运行时响应检查的边界见[向量回退](vector-fallback.md)。普通请求不借用管理员诊断身份计费；未知用量和未定价状态须原样保留，不能因使用共享名而视作零费用。

## 管理API

仅真实root账号会话可访问：`GET/POST /api/shared-virtual-models`，`PATCH/DELETE /api/shared-virtual-models/{id}`；编辑/停用携带`version`防并发覆盖。请求配置字段与私有调用策略相同；管理员元数据不属于可提交配置。共享模型是独立的schema40表，已有私有表与授权数据不自动迁移、合并或撤销。

`PUT /api/model-access?model=<标准逻辑模型名>`，JSON `{"internal_only":true}` 设置内部访问，false恢复直接调用的资格（仍须原有ACL）。`GET /api/model-routes` 标准模型带`internal_only`，另以`shared_virtual_models`提供管理员授权目录。API地址和模型名按现有URL编码规范使用。仅设置内部访问不会改动上游连接、凭据或模型映射。

普通调用的request、attempt与计费始终归实际用户和VKey，并按实际底层来源计价。共享和私有虚拟ID分别注明scope，避免同号混淆。配置变更及系统兼容探测记录实际root操作者。

## 删除与恢复

管理员共享模型和用户私有模型均支持回收站。列表中的“删除”需确认：立即停用并移出日常列表，保留配置、历史请求、诊断账本及审计；回收站可恢复。恢复后保持停用，确认配置并启用后才允许调用。

`POST /api/shared-virtual-models/{id}/trash`、`POST .../{id}/restore` 接受 `{ "version": 当前版本 }`，普通用户私有策略使用 `/api/account/virtual-models/{id}/trash` 和 `restore`；均要求原有 Cookie 授权及 CSRF。`GET` 列表加 `?trash=true` 仅列回收站，默认列表排除回收站。恢复时原名称已被使用会返回 409，不覆盖新入口；删除释放名称，允许新建同名模型。

原有 `DELETE /.../{id}` 保持“停用并保留在列表”的兼容语义，不代表移入回收站。回收站不提供永久删除接口。内部调用标志与用户授权不会因删除共享入口而被自动放宽，删除后也不能绕过共享入口直接调用底层模型。
