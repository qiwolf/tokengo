## 工具与角色

W04 将工具 strict 作为 omitted/true/false 三态。Chat/Messages 转 Responses 时，省略值明确转 false，避免目标默认值改变可选字段含义。Responses 转 Chat 时，只有能证明 schema 已严格的保守子集才将省略值转换为 true；schema 原样保留。不确定的引用、未知关键字、可选/开放属性或超过界限的 schema 拒绝，提示在 TokenGo 选择原生 Responses 来源。显式 true/false 保留，原生同协议保持原始请求。到 Messages 不能表达 strict=true 时继续拒绝，不以静默降级实现兼容。

W05 依精确来源、协议、型号将前导纯文本 developer 折叠为 system，覆盖文档已核实的 Qwen/Kimi/GLM 模型及既有 DeepSeek 行为。此转换折叠指令层级，不宣称独立 developer 优先级被完整保留。中途 developer、非文本或未知块拒绝，失败不改变原请求。QwQ/QVQ 明确不接受 system/developer 时拒绝，不降级到 user。未知来源、OpenAI/OAuth 及硅基流动托管来源保持各自合同，不按模型名称继承官方品牌规则。GLM-5.3-flash/flashx 角色取自其实际请求 schema，不据此扩展其工具能力。

实际硅基流动验收新增了独立来源证据：`Qwen/Qwen3.8-27B` 上游400明确返回 developer 不在 system/user/assistant/tool 枚举。TokenGo 为该精确托管型号增加自己的前导文本 developer→system 合同，不从官方 Qwen 继承；未知硅基流动型号仍保持原行为。后续 Chat 的连续 system 又被该来源拒绝，因此多个前导 system/developer 文本在网关内按顺序以两个换行连接成一条 system；原客户端请求保留。只有 role/content 的纯文本项可合并，需合并时存在 name/未知元数据/多模态则拒绝，不能删除字段；单项保留已有字段，中途 system/developer 不重排。其他厂商不适用此单 system 约束。

## 来源组合与型号

- DeepSeek：精确型号处理 thinking 与强制工具选择、JSON 格式及原生 Responses 的无状态/历史形态。原生 Responses 的 developer 不改成 user，不能等价支持时拒绝；不伪造摘要、加密推理或忽略状态参数。
- Qwen：核实工具选择、并行工具及思考开关组合。百炼托管 Kimi/MiniMax 不继承 Qwen 的 none→关闭适配，未知语义不能低估预算。
- Kimi：K3 原生 Responses 工具选择、effort、状态与格式合同；官方 `.ai`/`.cn` 精确端点和显式 profile 分别识别。新增仅该来源使用的原生 summary 历史归属证明，见下节。
- GLM：区分公开接口与官方 Coding Plan 路径，补型号、tool_stream/stream 和格式规则。官方 schema 与说明冲突处保留窄约束，未按相似型号推测 Flash 工具能力。
- Anthropic：精确增加 `claude-mythos-5-1` 的 adaptive 思考、强制工具例外、采样字段版本约束及普通接口输出上限；不授予账号访问资格，批处理 beta 上限不混入普通接口。
- MiniMax：区分 M3 Chat 省略 thinking 默认开启、Messages 省略默认关闭，以及 M3.1 固定开启；显式参数及 TokenGo 已配置映射默认值优先。跨协议仍无法解码的 active 思考在发送前拒绝，避免付费调用后才失败；M3 关闭思考的 Chat↔Messages 转换可用。完整思考方言编解码留给 W09，原生同协议透传不受此门禁影响。

### DeepSeek strict 的升级边界

[官方工具文档](https://api-docs.deepseek.com/guides/tool_calls/)将 strict 列为 Beta 能力，要求官方 `https://api.deepseek.com/beta` 且所有 function 均为 strict。TokenGo 对 strict=true 增加该来源检查；`/v1`、未知代理或仅手工声明品牌不足以证明 strict 保证，不自动更换端点、不偷偷改成 false。

这会使以往 Responses 省略 strict、转换到 DeepSeek 普通 Chat `/v1` 的部分工具请求提前拒绝。需要在 TokenGo 配置可证明的官方 Beta 来源或适用的原生 Responses 路由，不能靠更改客户端或绕过合同处理。此前非严格工具真实调用成功，不构成 Beta strict 验收。本批没有官方 Beta 账号真实验证，也未证明 `/v1` 实际会忽略或拒绝 strict。

### Kimi 原生 summary 历史

[Kimi Responses 文档](https://platform.kimi.com/docs/api/responses.md)允许将完整 output 原样追加到 input，包含 summary_text。实现保留原始 summary 项，不转换成 raw thinking；原生 JSON 与 SSE 最终快照登记证明，归属绑定 Key、会话、模型、来源、协议及来源代次。只在完整终态登记，单项/总量/数量均有界，与旧 ciphertext 摘要使用不同哈希域，旧 opaque 算法及 TTL/LRU 不变。

有效其他厂商原生 Responses 的旧显式会话摘要行为保留；匿名其他来源不能以空证明获得 summary 归属。失效、禁用、删除、代次或协议变更的来源不能回退到宽松旧路径。审查曾复现跨来源误拦与无关摘要占用 Kimi 配额两项回归，已补反例修复。升级前未签发证明的 Kimi 摘要历史不能安全追认，受影响会话需重新开始；无需修改客户端。
