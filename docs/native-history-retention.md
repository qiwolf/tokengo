# 原生加密历史的保留与回收

TokenGo默认处理所有调用方，不要求新增请求头、SDK改动或专用Key。原生加密字段及工具调用/结果保留原样；归属校验仍绑定当前Key、模型、会话（如有）、来源和凭据版本。

每个归属池的最近使用500条**指纹**受到软保护。指纹不是整段上下文，也不等于500个请求。匿名池按Key/模型/来源聚合；显式会话池继续隔离。500不是拒绝新调用的硬配额：近期活跃记录可以超过500，也可以超过原来的4096。

超出最近500条且至少24小时没有使用的记录，才有资格回收。排序依据`last_used_ms`，以签发时间和指纹作稳定并列排序；成功验证客户端带回的历史后先刷新使用时间，再在签发响应时回收该池的冷记录，每次最多删除1024条。单次有大量冷记录时分后续调用逐步回收，避免一次长事务。

不足500条的池在24小时后仍可保留；原有30天不活跃硬失效期限继续生效。整个长期不用的池仍按该硬期限清理。不存在活动调用时，不需要为了收缩单个池启动一个额外任务。

已回收、过期或不属于当前Key/来源的历史返回明确400说明，绝不放行未知加密材料、静默删输入或换来源重播。旧对话长期闲置后可能需要重新开始；这是明确的保留边界。

全局100万指纹、10万会话及单次响应数量/大小限制继续保留，防止资源无限增长。全局满额或数据库故障仍可导致本地状态错误，保留真实用量并记录固定脱敏原因码。本次修复不宣称所有资源/I/O故障都可在上游执行前预测。

不改变既有owner或摘要算法，仅追加归属/最近使用排序索引，不改表字段，不清空整个历史池、不轮换Key。旧记录按同一保留规则逐步处理，AG/HS及其他客户端维持原始实现。此前专用`X-TokenGo-History-Mode`分支已撤销，普通原样请求即适用该策略。

数据库迁移42仅新增`protocol_artifacts_owner_recent`覆盖索引，供窗口与冷记录查找使用；不改变数据格式。查询计划回归要求窗口查找使用该索引且不建立临时排序树。
