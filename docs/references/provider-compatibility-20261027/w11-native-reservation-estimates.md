# Native调用的本地预占估算

2026-10-28。缺少供应方硬上界的文档或实测只表示“未充分验收”，不自动关闭合法native调用。`ReservationEstimate`把本地预占量与上游是否硬限额分开；不修改价格、扣款、授权或实际usage算法。

对Total或已知答案+思考组合，继续按原精确合同计算，origin为contract，标注尚非live enforcement证明。对Unknown或答案cap外思考预算未知的情况，优先复用已有source配置额度，其次当前Price.max_output_tokens，再次网关既有4096默认政策，origin分别为source_configured/price_configured/gateway_default，confidence为estimate_not_upstream_bound。supplier_hard_cap_verified保持false。

估算至少覆盖显式可知输出下限及n个choices，配置的聚合准入额度不重复乘n。显式answer cap4096不能因price配置2048就被预占成2048或偷偷压低body；请求超过现有价格/source/余额/quota授权仍可具体拒绝。预准入和最终计量共用同一纯计算入口，防止前段只准入64、后段忽然按2048预占。

来源参数原形发送，不注入伪造thinking_budget，也不把答案cap改名成供应方总cap。显式总输出cap跨协议确实无法表达时仍可拒绝该具体请求；原生缺metadata与这种真实语义冲突分别处理。原有shape/type/数值、权限、Key状态、RPM/TPM与金额授权检查保留。

实际估算来源、confidence、semantics和预占量写在原 `billing_ledger.source_snapshot.reservation_estimate`，attempt另有固定脱敏说明；不记录prompt、Key或任意来源文本，不把估算冒充reported usage或供应方价格。实际usage到达后仍只结算一次；超过预占时保留observed_cost/overrun，扣款封顶已授权预占并沿原算法冻结后续预算。无价格保持unpriced，存在有限金额预算仍要求明确价格。

TPM维持现有本地预占口径：准入写入持久quota_events，结束不按实际usage回补token。使用估算不等于保证供应方实际token永不超出TPM，不能把现有机制描述成新增的硬上界能力。

新回归入口 `native_reservation_estimates`实际走loopback HTTP：无source metadata且已有Price输出2048时JSON/SSE均发送、wire cap64不变、唯一预占并按真实7/3结算；无Price时default4096并保持unpriced；有限金额预算缺Price、显式pricecap、模型权限、TPM仍拒；实际4096输出超过2048估算保留overrun/冻结后续调用。既有百炼native缺bounds用例按新裁决改为本地price估算正例，跨协议totalcap及min16负例保留。

独立真实SF三family角色入口也走正常新接入fixture：source context字段不设置，沿用原Price输入16384/输出1024，report从实际ledger读取price_configured估算；不新增32768“供应方上界”。原Qwen8call的请求和价格不改。真实14call与本轮测试结果须绑定最终源码，由root另记，不在本说明预先宣称通过。
