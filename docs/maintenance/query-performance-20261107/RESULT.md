# 查询性能修复与验收摘要

2026-11-07。本轮修复已完成生产配套验收，公开发行版本为v0.34.0-qiwolf.30；公开CI与资产状态见[发行收据](../../acceptance/2026-11-07-qiwolf30-release/README.md)。生产配套程序与公开构建分别记录，不把健康检查代替页面验收。

## 修复范围

模型评分从请求时间窗口驱动attempts索引，探索聚合使用实际SQLite版本可选中的部分覆盖索引；累计调用采用可重建的规范化、按请求去重派生汇总，首次预热与稳态读取分开。供应商/账务目录在单次响应内复用。

账本按绑定参数筛选、覆盖索引选ID及LIMIT+1确定游标；历史渠道名称通过不同channel ID逐次范围seek，再取最大账本ID的快照，保留最新名称/NULL回退。固定7种渠道、100与100000条账目均为434个VM步骤。默认有效对象筛选、历史账目、金额、未知用量及即时撤权口径保留。

个人和管理员统计减少重复窗口扫描并使用覆盖索引；管理员attempts按渠道流式汇总，AVG语义与实际bundled SQLite oracle对照。普通路由策略按需加载评分，维护信息使用精确COUNT/MIN快路径。协议TTL清理分批，读/claim/proof即时检查过期及owner epoch。schema45追加索引、可重建汇总及epoch，不删除业务历史。

## 实测与边界

构建测试使用Linux构建机；完整工作区基础批次1636通过、0失败、15忽略，Python合同13通过。最终单文件目录补丁另跑账务10项、配置目录、百万/十万规模与真实loopback并发，正式ELF升级/回退也通过；重叠测试不相加。

百万fixture各含100万requests/attempts/ledger，约3.73GB，error/snapshot包含1024字节合成padding；保留7万近期请求。29条管理路径每条5样本，另3轮12路真实HTTP读取竞争写入。模型最大34.378ms、对象2.511ms、有效账本4.130ms、历史账本6.944ms、全部账本4.524ms；并发请求最大136.728ms，含写入22.287ms。固定近期数据、旧历史10万至百万未重现这些路径按宽历史行数增长。

单owner50万请求/501000 attempts统计与费用精确oracle、owner隔离通过。最长管理员统计998.743ms接近1秒门槛，个人最长786.968ms；精确长窗口统计仍随命中行数增长。当前56用户/133Key/35渠道通过300ms门槛，十倍配置为record-only，用户列表最大304.377ms，不能称所有扩展规模都低于300ms。百万artifact活跃满载、旧epoch及过期积压容量分支通过。

生产维护期间使用503，排空、停服完整备份、离线迁移并核对原列投影守恒后切换；不是零停机。业务记录、配置及现有Web保持一致，备份已验证。新旧真实ELF的schema44→45及回退读写、晚到调用刷新验证来自合成库；不是生产灾难恢复演练。

上线后既有Chrome暖SPA切换供应商、模型、用户、额度、有效/历史/全部账本和24小时/7天总览，91响应全部200。模型12样本81.9—826.5ms（峰值与7天统计重叠），有效账本60.2—70.5ms、历史384.3ms、全部62.2ms、对象84.5ms、预算79.8ms、24小时204.6—298.8ms、7天798.8ms。共享连接长窗口锁争用仍可见；这是短期网络响应观测，不是冷缓存首开、INP或长期P95。生产自然流量快照132请求：130成功、0失败、2进行中。
