# 重排本地优先、繁忙时转云端

日期：2026-11-07。配套程序与指定路由已上线，六次真实合成300候选调用通过；`v0.34.0-qiwolf.31` 已正式发行，精确CI及9公开资产独立验收通过（11-08完成），正式包已完成生产切换和实际来源读回；详细状态以[本版发行收据](../../acceptance/2026-11-07-qiwolf31-release/README.md)为准。此页仅保留公开脱敏摘要。

## 路由行为与配置范围

共享入口 `bge-reranker-v2-m3-fallback` 保持名称。ordered目标依次为真实单节点模型映射 `bge-reranker-v2-m3-gpu03`、`bge-reranker-v2-m3-gpu01`、原硅基流动普通BGE来源。两个本地alias复用既有 `local_strategy=round_robin` 以忙时跳过；单节点轮转偏移恒0，优先级由共享目标顺序决定。共享目标必须核对实际模型映射，不能仅靠 `channel_ids` 声称只有一个节点。

本地两个source与credential并发上限各1，跨逻辑alias共享占用。空闲先用首选本地；其名额已占用时用次选本地；两者均占用则直接尝试云端。本次没有扩大用户模型、底层公开权限或来源授权，没有修改价格与调用方超时。升级发行包不会自动应用这组配置，也不会调整GPU节点参数。

“忙”仅指同一TokenGo进程接收的在途请求。直连GPU的请求、Whisper等其他任务不计入网关gate，多副本不共享分布式锁。该策略限制本地队列叠加，不保证GPU独占或指定完成期限。

## 程序修复与真实验收

旧程序在跳过繁忙本地、后备来源返回503后仍可能回头等本地。本次只结束“发现繁忙本地之后已经实际尝试后备”的回排；云端优先、先失败再遇忙本地的原等待仍保留。忙跳过不制造上游attempt、失败冷却或本地affinity，完整候选与输入窗口保持。

配套源码 `21953eee5bb0e02e8865f2d92e2ea0da14794e1f` 在build-test定向685项通过、4项忽略，Linux x86_64 release构建通过。旧实现失败日志保留；修复后的真实HTTP隔离回归覆盖渠道/凭据两种gate、三目标优先级、首选恢复、完整输入透传、云端503不回排和cloud-primary原等待。另三项配置事务测试覆盖单节点身份、保留新业务账的回滚、拒绝覆盖后续配置。不是正式发行CI结果，不与历史全量计数相加。

指定部署六次调用全部HTTP200，每次返回300个唯一有效索引及有限分数，且各只有一个真实上游attempt。两次空闲调用均首选本地，耗时2.346/2.266秒；四个300候选请求同时到达，本地各一笔、云端两笔，全部4.153秒完成。以同网关的请求与attempt时间推导，云端在本地完成前约两秒已开始；两条云端请求的网关总时长减attempt时长分别为43/36ms。它支持未先排本地再转云端，不等于精确分离全部路由、网络和记账耗时。

真实云端故障未人为触发；503行为由隔离回归验证。生产路由切换关闭入口、排空后备份，保持schema45及既有Web/CLI。回滚比较同一配置快照，保留期间新增业务账，不覆盖后来管理员改动或用旧数据库覆盖实时数据；失败恢复另留证并维持受控维护状态。
