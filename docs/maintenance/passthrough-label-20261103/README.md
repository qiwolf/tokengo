# 透传服务名称显示修复

后续状态（2026-11-03）：本修复已随[qiwolf.26](../../releases/v0.34.0-qiwolf.26.md)正式发行并配套部署237，真实Chrome名称与6项现有调用验收通过；公开产物独立验收通过。下文保留初次本地修复时的验证范围与历史状态，最新收据见[发行及237验收](../../acceptance/2026-11-03-qiwolf26-release/README.md)。

## 行为

总览统计从现有渠道元数据读取名称，包含HTTP透传服务。例如渠道51能显示`GPU03 CLIP`，停用服务也保留其名称。名称随统计请求刷新，改名不再依赖单独的大模型渠道名册。

名称缺失时，统计接口返回`channel_name: null`；总览、最近调用和请求详情使用`渠道 #编号（名称未记录）`，不把缺失名称推断为已删除。现有名称、请求数、成功率、路由、鉴权和LLM渠道配置清单保持原有语义。

## 实现范围

- `db::channels::names`只读取全部transport的ID/名称；现有`channels::list`继续只管理LLM连接。
- `/api/stats`复用既有`channel_name`字段，不增加接口或迁移数据库。
- 总览优先使用统计中随响应返回的名称，其次使用已加载的LLM名册；最终给出中性缺失提示。
