# 路线 B：身份、额度与计量

沿用已批准路线 B，暂不部署。路线 A 的最终 CI 必须通过后才合并我们的 main；B 在 codex/identity-metering 上实施。

## 交付契约

- users admin/user；所有历史 key 迁入 Legacy admin 用户，不改变旧凭据。新 vkey 一次显示、只存 SHA256 高熵摘要。禁用/撤销/到期/父 key 限制每次鉴权读当前数据库，缓存不能绕过。
- PanelAuth 管理全局 users/vkeys/pricing/budgets/usage；vkey 身份只管理自己的 key 和用量。用户与 key 白名单取交集，auto/fallback/诊断也不能越模型或来源/付费权限。
- 请求入口生成 AuthContext 并贯穿请求、每次渠道尝试与账本；用户/key 双层 RPM、TPM、并发限制，取消释放并发。
- 整数微美元、不可变价格版本，每次尝试先原子预占双层预算，获得额度才可发；已知 usage 按当时价格结算，missing/partial 单列保守估算。零已知与未知分开。
- 金融账本独立于诊断保留期；幂等结算，重启对未结预占保守收尾。真实上游超过声明 token 上界时保留真实成本，客户扣款不超预占并标记 overrun/冻结，不能声称限制了供应商账单。
- 每次尝试都留独立账：失败、取消、超时、重试/备用、工具多轮等按请求/尝试关联，不以最终成功掩盖已发生的耗用。

## 实施与必要验证

1. 身份/管理 API 与迁移，HTTP先红后绿；覆盖两个用户、多key、自助越权、子key扩权、禁用/撤销缓存竞态、重启和密钥脱敏。
2. 版本价格与预算账本，事务并发、双方预算、溢出、已知零/未知、重复结算、恢复、诊断清理不删账。
3. 双层请求与token/并发闸，边界/跨key合计/取消释放/重启窗口。
4. 网关按身份过滤全部候选（包括auto），按来源价格做费用权限检查，预占→发送→usage→收尾，撤销后新尝试拒绝。受控HTTP验证成功/失败/流取消/工具轮/向量账。
5. 独立安全复核，整仓测试和WASM检查；推送可审阅PR，核对CI，不部署。

尚不包含新UI、用户密码登录、组织树、协议转换和订阅适配。普通用户通过自己的vkey使用自助API。来源在本批沿用channel作为配置与上游凭据边界；后续provider account/deployment迁移保留账上快照。
